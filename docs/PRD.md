## 1. Цель проекта

Разработать Telegram-бота для автоматического поиска и публикации полезного технического контента.

Целевая аудитория:
- DevOps-инженеры
- Системные администраторы
- Разработчики
- SRE и Platform-инженеры

Бот периодически собирает материалы из русскоязычных источников и публичных Telegram-каналов и отправляет владельцу накопленные ссылки двумя дайджестами.

Результат отправляется владельцу в виде дайджестов со ссылками. Публикацию в другие чаты владелец выполняет средствами Telegram.

**Приложение не использует искусственный интеллект, LLM или OpenAI API.**

## 2. Технологические требования

- Язык разработки: Python 3.12+
- Telegram Bot API
- Размещение: Linux VPS
- Хранение данных: SQLite
- Получение материалов: RSS, публичные API, публичные веб-ленты Telegram
- Конфигурация: переменные окружения
- Запуск в production: systemd
- Архитектура: монолитное приложение с разделением ответственности между модулями

Избегать ненужных зависимостей и сложной инфраструктуры.

## 3. Источники контента

Все сайты явно перечислены в `SOURCE_EXTRA_URLS`. Для добавления, удаления и замены источника измените список URL и перезапустите бота. Пустое значение отключает сбор с сайтов.

Предусмотреть:
- Предустановленный список источников.
- Добавление дополнительных источников через `.env`.
- Исключение стандартных источников.
- Включение и отключение конкретных источников.
- Защиту от дублирования материалов.
- Логирование ошибок получения данных.

## 5. Формирование дайджестов

На выходе формируются два раздела.

- «Сбор с сайтов» — короткие заголовки и полные ссылки на статьи.
- «Сбор с Telegram» — заголовки или первые 100–200 символов текста и прямые ссылки на публикации.

Один материал занимает одну запись внутри раздела. Кнопки копирования и отправки в группу удалены. Если раздел превышает 4096 символов Telegram, он делится по границам записей. Каждая часть сохраняет название раздела и номер продолжения. Все ссылки сохраняются полностью. Для пустого раздела указывается отсутствие новых публикаций за период.

## 6. Сбор и отправка

При запуске бот очищает накопленные Telegram-обновления. Команды, отправленные во время остановки, пропускаются.

### 6.1. Подписка

- Владелец включает подписку через `/subscribe`, также принимается `/subscrube`.
- Все сайты и Telegram-каналы проверяются каждые `SUBSCRIPTION_INTERVAL_MINUTES` минут, по умолчанию 60.
- Ссылки на все новые публикации после включения подписки накапливаются в SQLite.
- Каждые `DIGEST_INTERVAL_HOURS` часов отправляются два дайджеста, по умолчанию каждые 10 часов.
- Тематика, возраст статей и лимиты ручных подборок при накоплении подписки не применяются.
- Ошибка отдельного источника не останавливает сбор остальных.
- Перезапуск сохраняет накопленные ссылки и текущие сроки. Просроченный дайджест отправляется после запуска.
- `/unsubscribe` приостанавливает подписку с сохранением накопленных материалов. Новое включение начинает новый период.

### 6.2. Ручной сбор

- `/digest` отправляет оба накопленных раздела из очереди и сохраняет срок следующей автоматической отправки.

- `/fetch` формирует дайджест всех ещё не показанных записей доступных лент сайтов немедленно.
- `/fetchtg` формирует дайджест всех ещё не показанных записей доступных веб-лент Telegram немедленно.
- Ручная выдача включает также ранее накопленные записи соответствующего раздела.
- После отключения подписки автоматический сбор и отправка приостановлены.
- Между ручными запусками каждой команды сбора выдерживается минута.

## 7. Команды и диагностика

Все команды доступны только владельцу в личном чате после регистрации через `/start`.

- `/help` выводит основные команды и текущий статус подписки внизу сообщения.
- `/status` показывает состояние подписки, интервал сбора, период дайджеста, последнее и следующее время проверки, срок следующей отправки, количество накопленных записей и результаты проверки каждого источника.
- Для каждого источника отображаются доступность, количество прочитанных и новых материалов.
- Ошибки чтения и неопределённый результат отправки дайджеста видны в диагностике.

## 8. Конфигурация

Настройки приложения должны задаваться через переменные окружения.

Все используемые параметры перечислены с комментариями в `.env.example`.

```dotenv
# Токен Telegram-бота и username владельца.
TELEGRAM_BOT_TOKEN=
ADMIN_USERNAME=

# Часовой пояс для времени в /status.
TIMEZONE=Europe/Moscow

# Все сайты: URL RSS / Atom / JSON Feed через запятую.
# Для удаления сайта уберите его URL из списка.
SOURCE_EXTRA_URLS=https://habr.com/ru/rss/flows/admin/articles/?fl=ru,https://www.opennet.ru/opennews/opennews_all.rss,https://www.linux.org.ru/section-rss.jsp?section=1

# Публичные Telegram-каналы через запятую, с @ или без.
TG_CHANNELS=@rbloog,@habr_com

# Интервал проверки всех сайтов и Telegram, в минутах (1–1440).
SUBSCRIPTION_INTERVAL_MINUTES=60

# Период отправки двух накопленных дайджестов, в часах (1–168).
DIGEST_INTERVAL_HOURS=10

# Путь к SQLite. Для systemd: /var/lib/telegram-digest/rblog.sqlite3.
# После изменения .env перезапустите бота.
DB_PATH=tg-digest.sqlite3

```

Изменения применяются после перезапуска приложения.

## 9. Хранение данных

Хранить в SQLite историю URL, очередь накопленных записей, подготовленные дайджесты и состояния их доставки, привязку владельца, подписку, сроки проверок и отправок, диагностику источников. База сохраняется между перезапусками.

## 10. Безопасность

- Доступ к управлению только у владельца.
- Проверять Telegram User ID для каждой административной команды и действия.
- Не хранить секреты в исходном коде и Git.
- Проверять входящие данные от внешних API.
- Ограничивать частоту запросов к источникам.
- Безопасно обрабатывать ошибки внешних сервисов.

## 11. Надёжность

- Автоматический запуск через systemd.
- Перезапуск приложения после сбоев.
- Логирование ошибок и основных операций.

## 13. Критерии готовности

MVP считается готовым, когда:

- Бот успешно запускается на Linux VPS.
- Ежедневный поиск выполняется автоматически.
- Бот получает материалы из нескольких источников.
- Владелец получает накопленные ссылки двумя дайджестами с автоматическим делением длинных разделов.
- Каждый материал содержит заголовок и ссылку на источник.
- Работают подписка, отключение подписки и диагностика через `/status`.
- Дайджесты отправляются в личный чат владельца без кнопок.
- Ошибки внешних источников не приводят к остановке бота.
- Основные сценарии покрыты тестами.
