# Архитектура

Один процесс Python получает команды владельца через long polling облачного Telegram Bot API. Перед запуском вызывается `deleteWebhook(drop_pending_updates=True)`. Команды за время остановки пропускаются.

## Модули

| Модуль | Ответственность |
| --- | --- |
| `config` | Проверка переменных окружения |
| `sources` | RSS, Atom и JSON Feed |
| `channels` | HTML веб-лент публичных Telegram-каналов |
| `selection` | Модель материала и нормализация ссылок |
| `storage` | Владелец, подписка, расписание, очередь, исходящие дайджесты и история |
| `telegram` | HTTPS-клиент облачного Bot API |
| `bot` | Команды, проверки источников, подготовка и доставка дайджестов |

## Подписка и расписание

`/subscribe` сохраняет дату включения. `digest_schedule` хранит ближайшие сроки проверки и отправки, дату последней проверки и JSON-отчёт по каждому источнику. Проверка выполняется с интервалом `SUBSCRIPTION_INTERVAL_MINUTES`, отправка — `DIGEST_INTERVAL_HOURS`. По умолчанию это 60 минут и 10 часов. Перед отправкой проводится дополнительная проверка, если срок дайджеста наступил раньше следующего сбора.

Время хранится с часовым поясом UTC, а в `/status` отображается в `TIMEZONE`. Первый период начинается при подписке. При смене интервала после перезапуска соответствующий срок пересчитывается от момента применения настройки. Для расписаний без сохранённых интервалов оба срока пересчитываются один раз.

## Сбор и очередь

Сайты и каналы читаются последовательно с тайм-аутами и повтором при временных сетевых ошибках. Ошибка одного источника позволяет обработать остальные. Результат каждого чтения записывается для `/status`. Подписка принимает все новые публикации после даты включения, независимо от тематики и возраста. Ручные команды включают все ещё не показанные записи из доступных лент.

`digest_queue` сохраняет username владельца, нормализованный URL, категорию `web` или `tg`, заголовок и дату. Внешний ключ `batch_id` связывает запись с конкретной частью дайджеста в `digest_outbox`. До подготовки части значение равно `NULL`. SQLite проверяет внешний ключ. При добавлении очередного URL бот проверяет его по индексам очереди и истории `seen_urls`. При первом запуске URL переносятся из прежней таблицы `articles`. При паузе подписки очередь сохраняется.

## Доставка

Из очереди формируются два раздела — «Сбор с сайтов» и «Сбор с Telegram». В каждом перечислены короткие заголовки и полные ссылки. Разделы длиннее 4096 UTF-16 единиц делятся по границам записей с нумерацией продолжений. Пустой раздел содержит уведомление об отсутствии обновлений. Кнопки удалены, callback-запросы игнорируются.

`digest_outbox` хранит подготовленный текст и состояние доставки. Все части периода, назначение им записей очереди и перенос срока следующего дайджеста фиксируются одной транзакцией.

| Состояние | Значение |
| --- | --- |
| `pending` | Дайджест ожидает отправки |
| `sending` | Запрос начат, повтор заблокирован до подтверждения |
| `sent` | Telegram подтвердил отправку |

Перед HTTPS-запросом состояние меняется на `sending`. После подтверждения URL записываются в `seen_urls`, а строки очереди этой части удаляются в той же транзакции. Текст хранится один раз в `digest_outbox`. При явном отказе Telegram состояние возвращается в `pending` для следующей попытки. Потеря ответа или аварийная остановка сохраняет `sending`, количество таких частей показывается в `/status`. Автоматическая повторная отправка неподтверждённой части блокируется, поскольку `sendMessage` не имеет ключа идемпотентности.

## Команды и совместимость

Владелец регистрируется командой `/start` от настроенного `ADMIN_USERNAME`. SQLite сохраняет числовой ID, используемый для проверки всех последующих команд. `/status` и `/help` доступны владельцу.

`/fetch` и `/fetchtg` отправляют соответствующий раздел сразу, включая уже накопленные записи. `/unsubscribe` останавливает автоматический сбор и отправку. Добавление новых таблиц сохраняет существующую базу, историю URL и привязку владельца.
